# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

NixOS flake-based system configuration for user `felixcool200`. Uses flake-parts + import-tree (Dendritic pattern) with hjem for user-level file management and wrapped packages for self-contained app config. Targets `x86_64-linux` with nixpkgs unstable channel and NUR.

## Key Commands

```bash
# Rebuild and apply configuration (aliases: rebuildOS)
nixos-rebuild --flake ~/Documents/nixos-config#<hostname> switch --impure --sudo

# Update flake inputs then rebuild (aliases: upgradeOS)
nix flake update --flake ~/Documents/nixos-config && nixos-rebuild --flake ~/Documents/nixos-config#<hostname> switch --impure --sudo

# Garbage collect old generations (aliases: cleanOS)
sudo nix-env --delete-generations +2 --profile /nix/var/nix/profiles/system && sudo nix-collect-garbage -d && nix-collect-garbage -d && sudo journalctl --vacuum-size=50M
```

Replace `<hostname>` with `systemd-boot-vm` or `grub-vm`. The shell aliases resolve this automatically via `config.networking.hostName`.

## Architecture

### Flake structure

`flake.nix` uses flake-parts + import-tree to auto-import all `.nix` files from `modules/`. No home-manager — user config is handled by hjem (file management) and wrapped packages (config baked into derivations via CLI flags).

### Multi-host setup

Hosts live under `modules/hosts/<hostname>/configuration.nix`. Each file defines both `flake.nixosConfigurations.<hostname>` and `flake.nixosModules.host<Name>`, importing `self.nixosModules.common` for shared config.

- **`systemd-boot-vm`** — VM with systemd-boot. Currently active.
- **`grub-vm`** — VM with GRUB (`/dev/vda`).

Shared config (feature imports, locale, user, packages) is in `modules/hosts/common.nix`.

### Wrapped packages (`modules/packages.nix`)

Self-contained packages with config baked in via `perSystem.packages`. Referenced as `self.packages.${system}.<name>`:

- **`wrapped-helix`** — `--config` flag with Dracula TOML
- **`wrapped-tmux`** — `-f` flag with tmux.conf
- **`wrapped-vim`** — `-u` flag with vimrc
- **`wrapped-nvim`** — runtime deps (lua, tree-sitter, nodejs, fd) on PATH
- **`wrapped-vscode`** — vscode-with-extensions override
- **`wrapped-waybar`** — `--config` + `--style` flags (includes weather/nightlight scripts)
- **`wrapped-hyprlock`** — `--config` flag with Dracula lock screen
- **`wrapped-hypridle`** — `--config` flag with idle/lock timeouts
- **`wrapped-hyprpaper`** — `--config` flag with wallpaper
- **`wrapped-swaync`** — `--config` + `--style` flags (symlinkJoin with swaync-client)
- **`wrapped-wlogout`** — `--layout` + `--css` flags (NDJSON layout, not JSON array)
- **`lsp-tools`** — symlinkJoin of all LSP servers
- **`ai-tools`** — symlinkJoin of claude-code

Most packages are wrapped using `Lassulus/wrappers` (`inputs.wrappers.lib.wrapPackage`) with `flags` for CLI args, `env` for environment variables, and `runtimeInputs` for PATH additions. Flag values must be strings (`"${derivation}"`), not raw derivations. Exception: `wrapped-swaync` uses `writeShellScriptBin` + `symlinkJoin` because `wrapPackage` would also wrap `swaync-client` with daemon flags.

### Feature modules (`modules/features/`)

Each file exports `flake.nixosModules.<name>`. Modules using wrapped packages follow:
```nix
{ self, ... }: {
  flake.nixosModules.<name> = { pkgs, ... }:
  let self' = self.packages.${pkgs.stdenv.hostPlatform.system};
  in { environment.systemPackages = [ self'.wrapped-<name> ]; };
}
```

### Desktop environments (mutually exclusive)

Selected by which import is uncommented in `modules/hosts/common.nix`:

- **`hyprland/`** — Hyprland (Wayland compositor). Currently active. System config in `conf.nix`, user config generated by wrapped packages + hjem for `hyprland.conf`. Sub-modules for greetd login manager. Walker is the app launcher (replaces wofi).
- **`gnome/`** — GNOME desktop. Currently commented out.

### Hyprland config files

- **`hyprland.conf`** — written via hjem (can't wrap Hyprland itself since greetd starts it)
- **`screenshot.desktop`** — written via hjem
- All other configs (waybar, hyprlock, hypridle, hyprpaper, swaync, wlogout) are baked into wrapped packages

### Theming

Dracula color palette is defined in `hyprland/colors.nix` as a Nix attribute set with hex, RGB, and rgba variants. Wrapped packages import this file for consistent theming.

### Other files

- `pi4NixConfig.nix` — Standalone Raspberry Pi 4 config (SSH, WireGuard, Raspotify). Not part of the main flake.
- `backgrounds/` — Wallpapers + dev shell for SVG conversion.
- Hardware config is at `/etc/nixos/hardware-configuration.nix` (not in repo, imported by path).

## Conventions

- New hosts: create `modules/hosts/<name>/configuration.nix` following the existing pattern (import `self.nixosModules.common`, set bootloader + hostname)
- New apps: create a wrapped package in `modules/packages.nix` and a feature module in `modules/features/<name>.nix`
- Apps needing system-level config should also have files under `apps/<appname>/conf.nix`
- The `--impure` flag is required because hardware-configuration.nix is imported by absolute path
- Hyprland shaders must use GLSL 3.20 ES (`#version 320 es`, `in`/`out` instead of `varying`/`gl_FragColor`, `texture()` instead of `texture2D()`)
- Night light uses hyprsunset (CTM-based, not captured in screenshots) toggled via waybar
- The current setup runs in a VM — GPU-dependent features (blur, screenshots in hyprlock, CTM color shifts) may not render visually
- GTK3 apps may crash due to GTK3/GTK4 conflicts in the Hyprland session — prefer Qt variants when available (e.g., `wireshark-qt`). Qt platform theme must not be set to `gtk3`; use `qtct`/`kvantum` instead
- wlogout layout format is NDJSON (one JSON object per line), NOT a JSON array
